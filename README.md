# mcp-code-mode

An MCP stdio server that implements Cloudflare-style Code Mode. One process loads Notion, GitHub, Vercel, and Supabase adapters. The model sees `list_apis`, `search`, `describe`, and `execute` instead of one tool per operation. `search` returns compact signatures. `describe` returns one operation's schemas. `execute` runs a Rhai script whose bindings call the APIs. Only the script's final value is returned.

The pilot adapter is the Notion public REST API (`Notion-Version: 2022-06-28`): search, create page, update page, update block, append block children, create database, and update database. Auth is the `NOTION_TOKEN` environment variable.

## Tools

| Tool | What the model sends | What comes back |
| --- | --- | --- |
| `list_apis` | nothing | Loaded API ids, base URLs, and operation counts |
| `search` | `query`, optional `adapter` and `limit` | Compact signatures: id, `METHOD /path`, one-line summary, required params as `name:in:type` |
| `describe` | `operation_id`, optional `adapter` | Parameters plus request and response schemas for one operation |
| `execute` | `code` | The script's final expression only |

Path and query parameters are keys on the single argument map. They are removed before the JSON body is sent.

```rhai
let found = search(#{ query: "Launch plan" });
let page = create_page(#{
    parent: #{ page_id: found.results[0].id },
    properties: #{
        title: #{ title: [#{ type: "text", text: #{ content: "Launch checklist" } }] }
    }
});
#{ page_id: page.id }
```

## Layout

| Crate | Role |
| --- | --- |
| `code-mode-core` | `Operation`, `Api` errors, `Clock`, `OperationInvoker` |
| `code-mode-index` | OpenAPI 3.x JSON loader, SQLite FTS5 search index, TTL response cache |
| `code-mode-sandbox` | Rhai engine. No filesystem, no `eval`, `print` discarded |
| `code-mode-adapters` | `ApiAdapter`, generic `OpenApiAdapter`, `NotionAdapter`, HTTP client |
| `code-mode-transport` | Newline-delimited JSON-RPC over stdio |
| `mcp-code-mode` | Binary, composition, token receipt |

`ApiAdapter` is the extension point. Notion, GitHub, Vercel, and Supabase are thin adapters over vendored OpenAPI files (`specs/vendor/SOURCES.json`). A new bearer-token API is another `OpenApiAdapter` plus a JSON spec. The tool list does not grow with the number of endpoints.

SQLite (`rusqlite`, bundled) stores the spec index and a TTL cache of successful GET/HEAD responses. POST, PATCH, PUT, and DELETE are not cached.

## Run

Rust is pinned in `rust-toolchain.toml` (1.99.1) because current crates require it.

```bash
export NOTION_TOKEN=ntn_your_integration_token
cargo run --bin mcp-code-mode
```

The server speaks MCP on stdin/stdout. Logs go to stderr.

```bash
cargo build
cargo test
cargo clippy --workspace --all-targets -- -D warnings
cargo run --bin token-receipt -- RECEIPT.md
```

`RECEIPT.md` is generated by `token-receipt`. It counts tokens with `tiktoken-rs` 0.6.0, encoding `o200k_base`. Regenerate it after changing tool schemas or workflow fixtures; `cargo test` checks that the file matches the generator.

Live Notion check, not part of `cargo test`:

```bash
export NOTION_TOKEN=ntn_your_integration_token
export NOTION_PARENT_PAGE_ID=the_parent_page_uuid
cargo run --bin notion-smoke
```

If either variable is missing, `notion-smoke` exits before it calls Notion. When both are set it creates a page under that parent, edits the page, creates a database under the page, edits the database, and prints an `o200k_base` receipt of the real response bodies versus the script's final value.

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `NOTION_TOKEN` | | Notion bearer token. Enables the `notion` adapter when `CODE_MODE_ADAPTERS` is unset |
| `GITHUB_TOKEN` | | GitHub bearer token. Enables `github` |
| `VERCEL_TOKEN` | | Vercel bearer token. Enables `vercel` |
| `SUPABASE_ACCESS_TOKEN` | | Supabase Management API token. Enables `supabase` |
| `CODE_MODE_ADAPTERS` | every adapter whose token is set | Comma-separated ids: `notion,github,vercel,supabase` |
| `CODE_MODE_ADAPTER_ID` | | Single adapter id, including a custom one used with `CODE_MODE_SPEC` |
| `CODE_MODE_TOKEN_ENV` | `API_TOKEN` for a custom adapter | Env var that holds the bearer token |
| `CODE_MODE_BASE_URL` | `https://api.notion.com` | API origin |
| `CODE_MODE_SPEC` | embedded Notion pilot spec | Path to an OpenAPI 3.x JSON file |
| `CODE_MODE_NOTION_VERSION` | `2022-06-28` | `Notion-Version` header |
| `CODE_MODE_EXTRA_HEADERS` | empty | `Name:Value` pairs separated by `;` |
| `CODE_MODE_CACHE` | `$XDG_CACHE_HOME/mcp-code-mode/cache.db` or `~/.cache/mcp-code-mode/cache.db` | SQLite path. `:memory:` disables the file |
| `CODE_MODE_CACHE_TTL` | `60` | Seconds. `0` disables the response cache |
| `CODE_MODE_HTTP_TIMEOUT_SECS` | `20` | Per-request timeout |
| `CODE_MODE_MAX_CALLS` | `32` | HTTP calls allowed in one script |
| `CODE_MODE_DEBUG` | unset | `1` logs method and path to stderr |

The embedded spec is `specs/notion-2022-06-28.json`. Notion's hosted MCP server (`@notionhq/notion-mcp-server` 2.6.1) speaks the 2025-09-03 data-source API instead. This pilot follows the database endpoints from the 2022-06-28 public REST API, which is what `create database` / `update database` map to. Point `CODE_MODE_SPEC` at another document to load a different surface.

## Claude Code

```bash
claude mcp add --transport stdio mcp-code-mode \
  --env NOTION_TOKEN=ntn_your_integration_token \
  -- mcp-code-mode
```

`mcp-code-mode` must be on `PATH` (`cargo install --path crates/mcp-code-mode` from this repo).

## Codex

`~/.codex/config.toml`:

```toml
[mcp_servers.mcp-code-mode]
command = "mcp-code-mode"
enabled = true

[mcp_servers.mcp-code-mode.env]
NOTION_TOKEN = "ntn_your_integration_token"
```
